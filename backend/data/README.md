# Recipe dataset

`recipes.csv` contains 100 recipes collected from [TheMealDB official API](https://www.themealdb.com/api.php). Its [terms](https://www.themealdb.com/terms_of_use.php) permit collecting API content; the collector does not scrape its website. Source recipe URLs, original publisher URLs, attribution and available image copyright/Creative Commons metadata are retained in the CSV. Images are linked, not downloaded.

## Import

From the repository root:

```sh
cd backend
npm ci
npm run recipes:validate
npm run migrate
npm run recipes:import
```

Configure `DB_HOST`, `DB_PORT`, `DB_NAME`, `DB_USER` and `DB_PASSWORD` in the repository root `.env` (see `.env.example`) or environment variables. Migrations use the existing project configuration. `recipes:validate` connects to no database. The importer does not require session configuration and imports into `DB_NAME`.

For a custom CSV path:

```sh
node scripts/import-recipes.js --csv /absolute/path/recipes.csv --dry-run
node scripts/import-recipes.js --csv /absolute/path/recipes.csv
```

The importer validates all 100 recipes, category/ingredient quotas, JSON, SQL field limits, duplicate source IDs/URLs/titles, duplicate ingredients and sequential steps before connecting. It resolves existing ingredients and aliases, adds missing catalog ingredients, and writes `recipes`, `recipe_ingredients` and `recipe_steps` in one transaction. A failure rolls back the entire import. A database advisory lock serializes concurrent runs of this importer.

Repeat imports update recipes with the same source URL while preserving their IDs, then replace their ingredient links and steps. Other recipes and existing ingredient categories remain untouched. This preserves references such as favorites. It rejects ambiguous pre-existing duplicate source URLs. Run the existing demo seed **before** importing if needed: the project's `npm run seed` deletes recipe/ingredient data and will overwrite this import when run afterward.

## Balance

Each of these source categories has 10 recipes: Beef, Breakfast, Chicken, Dessert, Miscellaneous, Pasta, Pork, Seafood, Side and Vegetarian.

Each of these assigned food ingredient groups has 10 recipes: beef, chicken, pork, seafood, pasta, rice, potato, legumes, egg and fruit. Each recipe is assigned one group that actually appears in its ingredient list. Beef/Chicken/Pork/Seafood/Pasta categories are assigned their corresponding staple group. The remaining categories distribute across the other five groups. A maximum-flow selection enforces both quotas at once.

Recipes can contain several common ingredients. The quotas apply to the assigned group, not the total occurrence count of every ingredient. Frequent supporting ingredients such as salt, onion and oil are naturally more common. Rice vinegar, fish sauce, vanilla beans and similar products do not qualify as their corresponding food staple. Obvious source category mismatches and duplicate normalized titles are excluded. `recipes-summary.json` reports actual ingredient occurrences and cuisine coverage as well as both quota counts.

## CSV to SQL mapping

| CSV fields | SQL destination |
| --- | --- |
| `title`, `description`, `servings`, `prep_minutes`, `cook_minutes`, `difficulty`, `image_url`, `source_url`, `tags` | `recipes` columns with the same names |
| `ingredients` JSON: `canonical_name`, `category` | Resolve/create rows in `ingredients` |
| `ingredients` JSON: `quantity`, `unit`, `optional` | `recipe_ingredients`, using generated recipe/ingredient IDs |
| `steps` JSON: `step_number`, `instruction` | `recipe_steps`, using the generated recipe ID |
| `source_id`, `category`, `cuisine`, `balance_ingredient`, publisher/video URLs, collection/attribution metadata | CSV provenance; category/cuisine/group are also stored in `tags` |
| Database IDs, `created_at`, `updated_at` | Generated by MySQL |

The `tags`, `ingredients` and `steps` cells contain JSON arrays; standard CSV quoting preserves commas, quotes and Unicode. Ingredient names are normalized to catalog names where appropriate, while original `source_name` and `source_measure` remain in the ingredient JSON. Compatible repeated quantities are added; incompatible units are left unavailable rather than converted incorrectly.

TheMealDB does **not** supply servings, preparation/cooking durations or difficulty. Those columns are blank and import as SQL `NULL`. They are not estimates. Descriptions are generated from source cuisine/category and are not copied publisher descriptions. Simple numeric and fractional measures are parsed to SQL `DECIMAL(10,2)` quantities; ranges, package expressions and prose such as “to taste” retain their complete source measure in the CSV and import with unavailable quantity/unit as `NULL`. The current SQL schema has no column for that original measure text, so the CSV remains its authoritative record. Recipe steps retain the source instructions in order, splitting nonempty paragraphs and removing standalone step-number labels.

Ingredient categories and tags support catalog lookup, but this dataset is not an independently verified allergy or dietary suitability assessment.

## Recollect and test

Python 3 is required only to recollect recipes. The importer uses the backend's existing Node dependencies.

```sh
npm run recipes:scrape
npm run recipes:validate
npm run recipes:test
```

The collector reads the 26 first-letter API endpoints with throttling/retries and caches responses under `/tmp/pantrychef-recipe-cache`. Use a fresh cache directory to force a fresh collection:

```sh
python3 scripts/scrape-recipes.py --cache /tmp/pantrychef-recipes-new-run
```

Tests use Node's built-in test runner, independent of the application integration suite. The MySQL test skips unless `RECIPE_IMPORT_TEST_PORT` is set. To run it against a **new disposable container** (port 33307 must be free):

```sh
docker run --detach --rm --name pantrychef-recipe-import-test \
  -e MYSQL_ROOT_PASSWORD=recipe-import-test \
  -e MYSQL_DATABASE=pantrychef_recipe_import_test \
  -p 127.0.0.1:33307:3306 mysql:8.4
# Wait until MySQL is ready, then run:
RECIPE_IMPORT_TEST_PORT=33307 npm run recipes:test
docker stop pantrychef-recipe-import-test
```

The MySQL test creates the actual ingredient/recipe tables, checks row totals and repeat imports, preserves an unrelated recipe and injects a late failure to verify rollback. Use a fresh container for each run; it does not reset existing databases.
